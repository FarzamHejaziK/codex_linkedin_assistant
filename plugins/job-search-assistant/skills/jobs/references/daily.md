# Daily Workflow

Read experience.md and session.md. Honor the user's scope; do not ask them to choose internal commands. An unspecified run covers up to three distinct jobs, with at most one proposed outreach action per selected job. Prioritize existing urgent work; find only enough new jobs to fill unused places. Prepare-only and time/count limits apply to every phase.

## Sequence

1. Resolve the saved workspace using local-persistence.md, then read its tracker, preferences, and any checkpoint. Resume missing local setup only as needed; missing optional platform configuration means Indeed is disabled, not a setup blocker.
2. Show up to three recommended actions using check.md and state the proposed run scope.
3. Process ready applications within scope; prepare concrete materials before asking for external-action approval.
4. Process referral work for selected jobs, including due follow-ups. Do not start a fresh unlimited referral sweep.
5. Discover jobs only if requested or batch capacity remains. Follow find.md, including LinkedIn-first discovery and approved fallback rules.
6. Newly found jobs without pending referrals may be prepared in the same run if within scope. They are never automatically submitted; use approvals.md.
7. Checkpoint after each completed step and before pausing. Stop at the count/time limit or a user stop instruction. A declined action skips that action; continue other authorized scoped work unless the user declines the whole run.
8. Summarize confirmed outcomes, prepared materials, blockers, and one next action. Link local artifacts. Separate prepared, uploaded, and submitted outcomes.

## Browser Failure

Run browser-preflight.md immediately before entering browser-dependent work. A failure blocks those steps; continue local checks and preparation from available saved sources. Do not bypass LinkedIn preflight or silently switch discovery sources. Record the precise blocker and resume point. Indeed failures affect only Indeed.

## Git

Do not automatically commit at the end of a daily run. Working tracker, session, resumes, profiles, application materials, and contact logs are private and ignored. If the user explicitly requests a commit of repository instructions, inspect the diff, stage only relevant non-private files, and leave unrelated changes untouched. Never force-add private files or use a broad add command to capture daily state.
