# Private Progress and Resume

Resolve the workspace with local-persistence.md first, including in a new chat. Use workspace-root `profile/session.md` for multi-step daily, application, or referral work. It is private and gitignored. It records workflow progress, not a second job database: `job_tracker.csv` remains authoritative for job state and contact logs for outreach evidence.

Record this short structure before a pause, after a completed step, and immediately before and after an external action:

```markdown
# Current Job Search Session
- Updated: <local date and time>
- Workflow and scope: <request, prepare-only or external actions, count/time limit>
- Selected jobs: <canonical URLs>
- Browser handoff: <browser name, relevant URL/tab reference, pending user step; no credentials>
- Completed: <steps and links to local artifacts>
- Pending: <next step per URL>
- Blockers: <missing information or browser issue>
- External outcomes: <confirmed with evidence, not attempted, or uncertain>
- Next action: <one concrete step>
```

Keep one current session. Preserve unfinished work when recording a new request; do not overwrite it silently. Link relevant application/contact notes instead of duplicating full personal information or entire forms. Do not store credentials or blanket approvals.

On “continue,” read the checkpoint, tracker, and relevant notes. Reconcile against confirmed outcomes, verify external uncertainty before retrying, and avoid duplicates. If no checkpoint exists, use the conversation and tracker to propose the smallest next action; ask only when the intended work cannot be identified.

For a browser handoff, retain the tab using supported tool behavior and save the URL. On return, verify the tab still exists, the account matches, and attachments/form fields are present; tab IDs and form state may not survive a restart. Reverify identity on provider changes.

Do not resume a previous time allowance automatically. Resume the remaining scoped batch; ask for a new time allowance only if needed. Keep prepare-only restrictions until the user explicitly changes them. Explain what has already completed and what comes next in one short update.
